# ADR: [short decision title]

Status: proposed / accepted / superseded / rejected

Date and accountable reviewer: to be recorded when decided

## Problem and constraints

State the concrete requirement, measured workload (or assumption), privacy and operating limits. Link canonical requirements rather than copying them.

## Alternatives

Compare viable approaches, including doing less. Cover complexity, correctness, cost, portability and reversal cost. Distinguish evidence from forecasts.

## Decision and consequences

Record the chosen option only after approval. Name what is deliberately deferred, risks accepted and assumptions that would invalidate the decision.

## Validation and reversal

Define the observable success/failure thresholds, validation scope, rollback/reversal path and next review trigger. Do not invent benchmark results or safety guarantees.

## Approval and dependencies

Record the actual approving authority and scoped decision reference. An accepted design is not automatically permission for paid execution, live integration, deployment, new credentials or expanded access.
